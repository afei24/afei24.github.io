大模型从”只会聊天”到”能干活”的关键一步：ReAct框架深度拆解

你的大模型还在”一本正经地胡说八道”？给它装上ReAct框架，让它学会”先想后做、边做边想”。

想象一个场景：你开了一家花店，每天早上需要给玫瑰花定价。你会怎么做？

你会思考——今天的进价是多少？然后你会行动——打开手机查一下今天的批发市场价格。接着你会观察——哦，今天进价涨了。于是你再次思考——那零售价得加多少？最后你行动——定出一个合理的售价。

这个”思考→行动→观察→再思考→再行动”的循环，人类每天都在不自觉地使用。而今天我们要聊的 ReAct 框架，就是把这个思维过程”灌”进大模型脑子里，让它从一个只会聊天的机器人，蜕变成一个能自主使用工具、解决复杂问题的 AI Agent。

一、只会推理？只会行动？都不够

在 ReAct 出现之前，大模型解决问题主要有两种流派：

  • 推理流（如思维链 Chain-of-Thought）：让模型一步步推理，但全程靠”脑补”，不查资料也不验证。结果？经常一本正经地胡说八道。
  • 行动流（如 WebGPT、SayCan）：让模型不断跟外部环境交互、搜资料，但缺乏有效的推理来综合信息，搜了一大堆最后可能得出错误结论。

举个论文中的经典例子：问大模型”除了 Apple TV，苹果遥控器最初是用来控制什么设备的？”

  • 标准回答：直接猜了个 iPod —— 错的。
  • 纯推理：一步步推理，推出 iPhone、iPad —— 还是错的。
  • 纯行动：去维基百科反复搜索，搜了一堆信息，最后决定”算了不搜了” —— 没得出答案。
  • ReAct：先推理→确定搜”Apple Remote”→观察搜索结果→再推理→搜”Front Row”→再观察→最终正确得出”键盘功能键”。

看到差距了吗？推理 + 行动，缺一不可。

二、ReAct 的核心：观察—思考—行动的循环

ReAct = Reasoning（推理）+ Acting（行动）。它不是简单的”想完再做”或”做完再想”，而是交错进行的：

每一轮循环中：

  • 思考（Thought）：模型分析当前状态，决定下一步做什么
  • 行动（Action）：调用外部工具（搜索引擎、计算器、数据库等）去获取真实信息
  • 观察（Observation）：接收工具返回的结果，为下一轮思考提供依据

这个设计有两个巨大的好处：

  1. 可解释性：每一步推理都有据可查，不再是黑盒
  2. 事实性：通过外部工具获取真实信息，大幅减少幻觉

三、LangChain 如何封装 ReAct：四个元素搞定一个 Agent

在 LangChain 中构建一个 ReAct Agent，只需要四个元素：

元素 作用
大模型（LLM） 提供逻辑引擎，负责推理和生成
提示（Prompt） 指导模型按 ReAct 框架思考
外部工具（Tools） 搜索引擎、计算器、数据库等
Agent 执行器（AgentExecutor） 管理整个”思考-行动”循环

五、AgentExecutor 内部到底发生了什么？（源码级拆解）

很多人用 LangChain 只是调 API，但想知道 Agent 为什么”智能”，必须钻进去看源码。我来带你走一遍 AgentExecutor 的核心流程。

5.1 AgentExecutor 本质上是一个 Chain

首先，在 LangChain 源码中，AgentExecutor 继承自 Chain 类。调用 agent_executor.invoke() 就是启动了一条链。你在控制台看到的第一行输出 > Entering new AgentExecutor chain... 就是从这里来的。

5.2 核心循环在 _call 方法中

AgentExecutor._call() 方法里有一个循环，不断地：

  1. 调用 _iter_next_step() 获取下一步的输出
  2. 判断输出：如果是 AgentFinish（任务完成）就退出循环；如果是 AgentAction（还需要行动）就继续

5.3 _iter_next_step 是真正的大脑

这个方法做了三件事：

  • Plan（计划/思考）：调用大模型，把当前状态和 ReAct 提示一起喂进去，让模型输出下一步该做什么
  • Action（行动）：如果模型说要调工具，就执行 perform_agent_action()，去调用对应的工具
  • Observation（观察）：把工具返回的结果记录下来，作为下一轮 Plan 的输入

5.4 模型的”思考”到底返回了什么？

当大模型被调用后，它返回的不是普通文本，而是一个结构化的 AgentAction 对象：

注意这里有两个关键信息：

  • tool：告诉系统”我要用搜索工具”
  • tool_input：告诉系统”搜什么内容”

这就是 Function Calling（或者叫 Tool Calls）的本质——大模型不是真的去调工具，而是输出一个结构化的意图，然后由 AgentExecutor 去执行这个意图。

5.5 工具执行后的 Observation

搜索工具返回了一堆市场信息后，这些信息会作为 Observation 注入到下一轮 Prompt 中。大模型看到这些真实数据，再决定下一步：

  • 如果信息够了，就输出 AgentFinish，给出最终答案
  • 如果还需要进一步操作（比如这次需要计算），就输出新的 AgentAction

5.6 三轮回合，任务完成

在我们这个鲜花定价的例子中，Agent 经历了三轮思考-行动循环：

  • 第一轮：思考→决定搜索→搜索”玫瑰进货价”→观察到价格约 25 元
  • 第二轮：思考→需要计算→调用计算器→25 × 1.05 = 26.25
  • 第三轮：思考→信息已足够→输出 Final Answer

至此，AgentExecutor 的循环结束，任务完成。

六、为什么 ReAct 框架是 Agent 的里程碑？

回顾整个流程，你会发现一个核心转变：

没有 ReAct 的大模型 = 一个知识渊博但只会”脑补”的学者
有了 ReAct 的大模型 = 一个会查资料、会用计算器、会一步步验证自己想法的问题解决者

ReAct 框架之所以重要，是因为它解决了三个关键问题：

  1. 幻觉问题：通过接入外部工具获取真实信息，而不是依赖模型内部可能过时或错误的知识
  2. 可解释性问题：每一步的 Thought-Action-Observation 链条都有明确记录，你可以清楚地看到 Agent 为什么做了某个决策
  3. 能力边界问题：大模型不擅长数学？没问题，给它配个计算器工具。大模型不知道最新信息？没问题，给它配个搜索引擎。ReAct 让大模型的能力边界不再等于其训练数据的边界。

七、写在最后

本章深入 AgentExecutor 源码的调试过程，揭示了 LangChain 封装 ReAct 的完整机制。这种”推理与行动协同”的模式，让 Agent 不再是被动地回答问题，而是主动地规划、执行、验证、调整。

未来，随着具身智能（Embodied AI）的发展，ReAct 及类似的框架将赋予 Agent 在虚拟世界或现实世界中进行更复杂交互的能力——在虚拟世界中导航，在现实世界中操控物理对象。Agent 的应用边界将远远超出今天的想象。

如果你正在做 AI Agent 相关的开发，深入理解 ReAct 框架的运行机制，绝对是你绕不过去的一课。不要只满足于调 API——钻进源码，看到 AgentExecutor 的循环是怎么跑的，你才能真正理解”智能体”的智能从何而来。
